⚖ Read this before anything else — authorization is the line. Every technique here is taught for authorized testing: your own lab, a CTF, or an engagement with written permission that defines the scope. Running these tools against systems you don't own or aren't contracted to test is a crime in most countries (in the U.S., the Computer Fraud and Abuse Act). Skill without authorization isn't pentesting — it's an offense. Jump to Rules of Engagement & Ethics for how the pros stay on the right side.
Orientation

What a penetration test really is

A penetration test is an authorized, simulated attack on a system, network, or application. The goal isn't to "break in" for its own sake — it's to find the weaknesses a real attacker would use, prove they're exploitable, and hand the owner a clear path to fix them.

🔍 Vulnerability scan ≠ pentest

A scan lists possible weaknesses automatically. A pentest verifies them by hand and shows real business impact. Scanning is one phase inside a pentest.

🧭 It follows a lifecycle

Real tests are methodical, not random. The same ordered phases repeat every engagement — that repeatability is what makes results trustworthy.

📝 The report is the product

The client pays for findings they can act on. Clean evidence, severity, and remediation steps matter more than the flashiest exploit.

The core

The five phases, in depth

Each phase below follows the same shape so it's easy to study and easy to edit: what goes in, what you do, what comes out, plus a click-to-open deep dive and the go-to tools.

① Reconnaissance — gather intelligence

Learn everything you can about the target before touching it. Good recon makes every later phase faster and quieter.

In →

Scope & targets from the rules of engagement.

Do

OSINT, DNS/WHOIS, employee & tech footprinting.

Out →

A profile: domains, IP ranges, people, tech stack.

Passive vs. active is the key distinction here:

Passive reconNo packets to the target. Public records, search engines, social media, certificate transparency. Effectively undetectable.
Active reconYou interact with the target (e.g. DNS lookups against their server, light probing). Faster, richer — but it can be logged.
  • Network footprint — domains, subdomains, IP ranges, ASN.
  • Technology stack — web servers, frameworks, CMS, cloud providers.
  • Human layer — employees, emails, job posts (which leak the tech they run).
  • Leaked data — credentials in breaches, secrets in public code repos.

OSINT is the heart of this phase. The OSINT Framework is a great map of where to look.

Tools: whois · dig / nslookup · theHarvester · Maltego · Shodan · crt.sh

② Scanning & Enumeration — map the attack surface

Turn the recon profile into a precise map: which hosts are alive, which ports are open, which services and versions are running, and what accounts or shares exist.

In →

Target ranges and domains from Phase 1.

Do

Host discovery, port + service scanning, vuln scanning, enumeration.

Out →

A live map of services, versions & likely weak points.

Scanning answers "what's there?" — live hosts, open ports, service versions. Enumeration goes deeper and pulls named resources: user accounts, network shares, SNMP data, directory structures. Enumeration is where a generic "port 445 is open" becomes "here are the usernames and shares."

Map findings to known CVEs — NVD and MITRE ATT&CK help connect a version to a technique.

# Classic two-step: discover, then scan deeply
nmap -sn 10.0.0.0/24                 # ping sweep — who is alive?
nmap -sV -sC -p- -oA scan 10.0.0.5   # all ports, versions, default scripts

Tools: Nmap · OpenVAS · Nessus · RustScan · enum4linux-ng

③ Gaining Access — exploit a weakness

The phase everyone pictures. Use a vulnerability from Phase 2 to get a foothold — a shell, a session, valid credentials, or application-level control.

In →

Prioritized weaknesses + working exploit path.

Do

Exploit, brute-force, phish, abuse misconfigurations.

Out →

Initial foothold + proof of access (evidence).

  • Software exploits — known CVEs against unpatched services/apps.
  • Web app flaws — injection, broken auth, SSRF (see the OWASP Top 10).
  • Credential attacks — password spraying, reused/leaked creds.
  • Social engineering — phishing the human layer.
  • Misconfigurations — default creds, exposed admin panels, open buckets.
Stay in scope. A working exploit is only valid if the target is in the authorized scope. "It was reachable" is never the same as "it was allowed."

Tools: Metasploit · Burp Suite · sqlmap · Hashcat · Exploit-DB

④ Maintaining Access — persist, escalate, pivot

Prove the impact. A foothold as a low-privilege user is a finding; domain admin reached from that foothold is the story the report needs to tell.

In →

Initial foothold from Phase 3.

Do

Privilege escalation, persistence, lateral movement, data discovery.

Out →

Demonstrated business impact + scope of compromise.

  • Privilege escalation — low-priv → admin/root/SYSTEM.
  • Persistence — a reliable way back in (documented, then removed at the end).
  • Lateral movement — pivot from one host to others; this feeds new recon.
  • Goal demonstration — reach the "crown jewels" the scope defined (e.g. a database, domain controller, or sensitive file) — access, don't exfiltrate.
Ethical persistence. In an authorized test you note exactly what you planted and where, so every change is cleanly reversed during Phase 5.

Tools: PEASS-ng (linPEAS/winPEAS) · BloodHound · Mimikatz (credential study) · C2 frameworks (concept only)

⑤ Covering Tracks & Reporting — clean up and deliver value

The phase that separates a criminal from a professional. A real attacker hides; a pentester documents everything and restores the environment.

In →

All evidence, notes & changes from Phases 1–4.

Do

Remove artifacts, restore state, write the report, debrief.

Out →

A clear, prioritized report + a clean environment.

"Covering tracks" — the attacker's view (study, don't imitate). Real adversaries clear logs, hide files, and time-stomp to evade detection. You learn this so the blue team can detect it — not to hide your own work.

Cleanup & reporting — the pentester's job. You reverse your changes (remove tools, accounts, persistence) and produce the deliverable:

  • Executive summary — business risk, in plain language.
  • Technical findings — each issue with evidence, severity (e.g. CVSS), and reproduction steps.
  • Remediation — concrete, prioritized fixes.
  • Debrief — walk the client through it.
The report is the product. An engagement no one can act on was a waste of everyone's time, no matter how clever the exploit.

Common tools & techniques by phase

Same tools show up again and again — but why they fit a phase is what matters for the exam and the job. Click a phase to see its go-to tools and techniques, and the reason each earns its place.

WHOIS · dig · nslookupDNS & registration lookups (footprinting). Reveal domains, IP ranges, name servers and registrant info without touching the target — pure passive mapping.

Google dorkingAdvanced search operators. Surface exposed files, login portals and leaked data that's publicly indexed — cheap, quiet wins.
MaltegoLink-analysis / OSINT graphing. Visualizes relationships between people, domains and infrastructure to plan realistic attack paths.

linPEAS · winPEASPrivilege-escalation enumeration scripts. Surface misconfigurations and privesc paths from a low-priv foothold — the route to admin/root.
BloodHound · SharpHoundActive Directory attack-path mapping. Graphs the shortest path to Domain Admin via ACLs and sessions — turns a foothold into full compromise.

Meterpreter / C2 (concept)Post-exploitation session & control channel. Stable channel to manage access; in a test it's documented and torn down during Phase 5.

Rules of engagement & ethics

Before Phase 1 ever begins, the boundaries are set in writing. This is the Rules of Engagement. Hover the checklist items for why each matters.

The authorization checklist

  • Defined scope — in/out of bounds, in writing.
  • Written authorization — the "get-out-of-jail" letter.
  • Testing window — when you're allowed to test.
  • Emergency contact — who to call if things go wrong.
  • Data handling — how to treat anything sensitive.

The pentester's mindset

  • Authorized, always. No scope creep, ever.
  • Do no harm. Avoid actions that could crash production.
  • Stay confidential. Findings belong to the client.
  • Report honestly. Including what you couldn't break.

Frameworks worth knowing: EC-Council Code of Ethics · OSSTMM
